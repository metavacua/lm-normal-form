## Purpose

A published language model exists in this repository's experiments as several
files: Hugging Face's `model.safetensors`, an ONNX graph, a GGUF file, the
Rust and burnpack that Burn generates from the ONNX graph, and the
`wasm32v1-none` module built from that Rust. Batch 0011 compared the tensors of
three of these for the Instruct model; batch 0026 built and ran the module. No
batch has laid the five side by side as graphs, for the base model as well as
the Instruct model, or said which part of each file is the model and which is
the program that reads it. This batch does that, and adds one question from the
side of formal languages.

1. **The graph each format states.** What a file says about structure without
   a name convention: nodes, edges, and which of them have an identifier that
   the file itself supplies.
2. **The maps between the graphs.** For each pair of formats, which node
   corresponds to which, under which relation (identical, transposed, widened,
   reshaped, permuted), decided by content and not by name, with every
   exception listed.
3. **Base against Instruct.** The two checkpoints share a configuration except
   in token ids and in fields that do not change the graph (`mlp_bias` is
   `false` in one and absent in the other, which `transformers` reads as
   `false`), so the program they need should be the same. The batch asks which
   artifact is the same file for both and which is not.
4. **Blank and empty structures.** Section "Blank and empty" below.
5. **A rule for the graph.** The graphs are written as ground RDF: no blank
   node, and an identifier for every node that the file itself supplies or that
   its position gives. The batch checks that this can be done for every format
   and counts what in each format cannot serve as an identifier.

## Blank and empty

In formal language theory the empty word ε is the identity of concatenation
(wε = εw = w). A production with ε on its right-hand side erases what it
rewrites. A grammar in which no rule shortens a sentential form (a
non-contracting grammar; the context-sensitive languages) has a decidable
membership problem; an unrestricted (type 0) grammar, whose rules may erase and
contract, defines the recursively enumerable languages, which is the class of
the Turing machines, and a Turing machine's tape is blank wherever nothing has
been written. In RDF a blank node is an existential variable (RDF 1.1
Semantics), and a blank node has no identifier that outlives the file.

None of the formats below is treated as a grammar of one of these types, and no
membership problem is decided here. The words are used to classify constructs.
A construct is **blank or empty** in one of six senses; a sense is a property of
a construct, counted, and the batch claims nothing about a construct beyond the
count unless a prediction says so.

| sense | what the construct does | the analogy |
|---|---|---|
| **A, anonymous** | a node, tensor or function with no identifier in the file, or an identifier that is empty or shared | the blank node: something exists and has no name |
| **B, absent** | a position or a value that the format lets be missing: an optional input written as the empty string, a tensor that is not stored because it is an alias of another | the empty word where a symbol is expected |
| **C, neutral** | an operation that returns what it was given: `Identity`, `nop` | ε as the identity of concatenation |
| **D, unused capacity** | space that holds nothing: padding, zero-filled pages of linear memory, a weight slot declared and not yet filled, a unit that is never read | the blank symbol of the tape |
| **E, non-portable label** | an identifier that a tool made up for one file: a random id, a counter, a hash of a build | the label of a blank node, valid only in its file |
| **F, unbounded control** | a construct that lets a computation run for a number of steps that the file does not state: a `loop`, a recursion, an indirect call, a subgraph operator | what makes a language unrestricted |

Which senses a format holds decides what a graph of it may use as an
identifier. A node of sense A has only a positional name (its index); a label
of sense E must not be part of an IRI.

## The rule for the graphs

Every graph of this batch is written as N-Triples (and the whole as N-Quads, one
graph per artifact) with IRIs `urn:lmnf:b28:…` minted from an identifier that is
**declared** in the artifact (a tensor's name; a key; a statement's name) or
**positional** (the index of an ONNX node; the index of a function; the slot of
an input). An identifier that differs between two generations of one artifact
(`param_id`) or that is empty or repeated is never part of an IRI. A graph
**conforms** when (a) no subject, object or graph name is a blank node, (b) the
sorted file is byte-identical when written twice, and (c) no two nodes share an
IRI. (a) is checked by a SPARQL `ASK` with `isBlank` in Oxigraph, which is a
standard query on a standard store.

The relations of the maps are edges between node IRIs, one predicate per
relation, so that nothing needs reification.

## The hypothesis, and what would refute it

**H.** For SmolLM2-135M and SmolLM2-135M-Instruct, the five formats hold one set of
272 weight tensors up to a finite list of named relations (transposition,
widening, the tied copy, llama.cpp's query and key permutation, the reshape of a
scalar); the two checkpoints differ in their weights and in nothing the program
states; and every graph of this can be written as a ground graph, because each
format supplies a declared or positional identifier for each of its nodes, except
where the identifier is run-dependent (`param_id`), empty or repeated, which the
census counts.

H is refuted by a tensor of any artifact that has no relation to a safetensors
tensor or to a constant of the program; by a difference between the programs of the
two models (the skeleton, the generated Rust, the module); or by a node of a graph
for which neither a declared nor a positional identifier exists. A cell that cannot
run, or a control that fails, makes the predictions that depend on it not checked,
and a batch with a prediction not checked fails.

## The claim it would license, and nothing more

If the predictions below hold, then for these two checkpoints, at these
versions, the five formats hold one set of 272 weight tensors up to a finite
list of named relations; the two checkpoints differ in their weights and in no
statement of the program (the ONNX graph, the generated Rust, the module); every
graph can be written as a ground graph with an identifier for every node; and
the blank and empty structures of each format are the ones counted. It licenses
nothing about other models, other quantizations (a GGUF type other than F32 and
BF16), other converters or versions of them, other targets than
`wasm32v1-none`, or the behaviour of the module beyond the three prompts of
batch 0010.

## Predictions, with severity

Severity is how likely the prediction is to fail if the construction is wrong,
not how likely it is to fail. A prediction about a model is stated for both
models unless it names one.

**Inputs**

- **P1, a control, low severity.** `model.safetensors` of each model has 272
  tensors, all `BF16`, 134,515,008 elements, no `lm_head.weight`, the metadata
  `{"format": "pt"}`, offsets that are contiguous, and a header whose trailing
  bytes after the JSON, if any, are spaces. Refuted by any difference. (Batch
  0011's P1 for the Instruct model.)
- **P2, a control, low severity.** Optimum's export of each model has 273
  initializers with 162,826,560 elements and 7,360 nodes; the Instruct model's has
  the sha256 `7583ca8fdc74af2ca98fb5cc254ea305f840ec3a2a1998c4be1f7c9a35a9df47`.
  Refuted by a different count or digest. A different digest is recorded and the
  new graph used; nothing below depends on the digest being equal.

**Tensor maps**

- **P3, moderate severity.** Between the safetensors file and the ONNX export, for
  each model: the 272 keys are the same set; the relations over the 273
  initializers are 211 `transposed` (the 210 linear weights and the tied head),
  1 `identical` (the embedding table) and 61 `identical` (the norm vectors); the
  embedding tensor is matched twice. Refuted by any other count. (Batch 0011's
  P7 and P8, for the base.)
- **P4, high severity.** Between the safetensors file and the GGUF file made with
  `--outtype f32`, for each model: the GGUF has 272 tensors; the relations are 212
  `identical` (the embedding, 150 of the linear weights, 61 norm vectors) and 60
  `permuted` (the query and key weights of the 30 layers) and none `none`; and
  every permuted tensor equals the llama.cpp permutation of the safetensors
  tensor with 9 heads for the query and 3 for the key. Refuted by another count,
  by one tensor with no relation, or by another permutation. This is the one place
  in the five formats where a conversion reorders the weights of a matrix, and it
  rests on the source read at the pinned tag and not on a run.
- **P5, moderate severity.** The GGUF made with `--outtype bf16` holds the same 272
  keys as the one made with `f32` (equal `bag_root`); its tensors are 211 `BF16`
  (the embedding and the 210 linear weights) and 61 `F32` (the norm vectors); the
  `f32` file's are all `F32`. Refuted by any difference.
- **P6, moderate severity.** Between the ONNX export (its initializers and the
  values of its `Constant` nodes) and the burnpack of the `File` strategy, for
  each model: the 273 burnpack tensors of 256 bytes or more are 271 `identical`
  and 2 `both` (the tied pair); of the 396 smaller ones 153 are `identical` and
  243 `reshaped`, and none is unmatched. Refuted by any other count. (Batch
  0011's P11, for the base.)
- **P7, high severity.** Between the base and the Instruct model, in the
  safetensors file, the ONNX export, the GGUF file and the burnpack, the 272 weight
  tensors share no key (so no weight of one is a weight of the other, in any
  layout); the 396 burnpack tensors of fewer than 256 bytes (constants of the
  program) share every key, equal in every bit. Refuted by one shared weight key or
  by one constant that differs. (Batch 0011's P17 for the safetensors file; the
  constants are new.)

**Configuration**

- **P8, low severity.** In the GGUF files of both models, `general.architecture` is
  `llama`; `llama.block_count`, `llama.context_length`, `llama.embedding_length`,
  `llama.feed_forward_length`, `llama.attention.head_count`,
  `llama.attention.head_count_kv`, `llama.rope.freq_base` and
  `llama.attention.layer_norm_rms_epsilon` equal `num_hidden_layers`,
  `max_position_embeddings`, `hidden_size`, `intermediate_size`,
  `num_attention_heads`, `num_key_value_heads`, `rope_theta` and `rms_norm_eps` of
  `config.json`; `llama.vocab_size` and the length of `tokenizer.ggml.tokens` are
  49,152; `llama.rope.dimension_count` is 64. Refuted by any difference.
- **P9, moderate severity.** Between the GGUF files of the two models, the keys
  whose values differ are `general.*` keys, `tokenizer.chat_template` (present in
  the Instruct file only), and the special-token ids (`tokenizer.ggml.bos_token_id`
  0 and 1, `tokenizer.ggml.eos_token_id` 0 and 2, and the padding id if present).
  No `llama.*` key differs, and `tokenizer.ggml.tokens`, `tokenizer.ggml.merges` and
  `tokenizer.ggml.token_type` are equal. Refuted by any other difference.

**The program is one program**

- **P10, moderate severity.** The two ONNX exports have the same skeleton: the same
  nodes in the same order with the same domain, operator type and attributes
  (tensor-valued attributes by their digest), the same wiring once each value name
  is replaced by the index of its first occurrence, and the same names, shapes and
  types for the graph's inputs, outputs and initializers (not their contents). The
  skeleton sha256 is equal. Refuted by one difference.
- **P11, moderate severity.** The generated Rust of the two models differs only in
  the comment that names the input path: one line for the `Bytes` source, and for

  constructor. Refuted by any other difference.
- **P12, moderate severity.** The `wasm32v1-none` modules built from the `Bytes`
  sources of the two models are the same file (equal sha256). Refuted by different
  digests; then the functions whose bodies differ are listed.
- **P13, low severity.** No weight is in the module: for each of the 273 large
  tensors of the burnpack, its first 256 bytes do not occur in the `.wasm`. Control:
  the same search over the burnpack finds all 273. Refuted by one occurrence in the
  module or by a control that does not find all.
- **P14, high severity.** The module of each model, given that model's `model.bpk`
  by the host, runs the three prompts to the end and agrees with ONNX Runtime
  (graph optimization on and off) as batch 0026's P7 and P8 require: the same five
  most probable ids in the same order, each of the five probabilities within 1e-4,

**Ground graphs and identifiers**

- **P15, low severity.** Every graph of the batch conforms (a, b and c above). Control: a copy
  of one graph with one blank node added is reported by the `ASK`, and the same copy is

- **P16, moderate severity.** Every node of the Optimum export has a non-empty name,

## Rivals to exclude

- **Pairing by names.** Every tensor map is decided by digest; names only label. The
  pairing by names is compared to it as batch 0011's P9.
- **A shared misreading of GGUF.** Two readers (C5). A permutation that is not llama.cpp's
  would leave `none`, not `identical`.
- **The same weights.** Each job records the sha256 of the safetensors file it used, and
  the jobs of one model must agree.
- **The module is not what ran.** The sha256 of the `.wasm` and of the `model.bpk` given to
  the host are recorded; the module of one model is the file run for it.
- **Agreement on the last position only.** The logits of every position are compared.
- **A graph that is ground by omission.** A graph with no blank node because the node was
  dropped. Each graph's node count is compared with the count of the artifact's own
  census; P15 fails if they differ.
- **Not excluded:** other prompts, padded or cached inputs, other models, GGUF types other
  than F32 and BF16, other converters, browsers, threads, SIMD; that a count of blank or
  empty constructs depends on the exporter and its version.
