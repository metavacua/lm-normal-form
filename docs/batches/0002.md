# Batch 0002: existing tools on sampled models

- **Registered:** 2026-10-05, before any cell ran.
- **Status:** not yet run. Results are appended below once CI has produced them.
- **Branch:** `batch/0002-existing-tools`. **Workflow:** `.github/workflows/batch-0002.yml`.

## Purpose

Programs that already run known-to-work language models exist. So do tools
that read, convert and describe such models. This batch runs twelve of them,
unmodified, on a small sample of models, to find out what each one gives,
what it needs, and where they disagree with one another.

The running programs are the baseline. Everything else in this project is to
be checked against them.

## Rules for this batch

- **No code of this repository's own.** Every step invokes an existing tool.
  What is hand-written is this document and the workflow's choice of tools,
  options and samples.
- **An observation is a workflow step marked `continue-on-error`.** Its
  recorded outcome, success or failure, is the result. A tool that fails on a
  sample has told us something.
- **A job fails only when setup fails:** an install or a download broke.
- **Tool runs go through GNU `time`,** so that what each one needs is on
  record before anything like it is run on a smaller machine.
- **Models are taken at their current revision.** Revisions and digests are
  recorded where a file is downloaded whole.
- **The prompt** is `The capital of France is`, as in batch 0001.

## Samples

- `HuggingFaceTB/SmolLM2-135M-Instruct`, and for configurations also the
  360M and 1.7B models of the same architecture.
- `openai-community/gpt2`, and for configurations also `gpt2-medium` and
  `distilbert/distilgpt2`.
- `Qwen/Qwen3-0.6B`, and for configurations also the 1.7B and 4B models; its
  published GGUF file `Qwen/Qwen3-0.6B-GGUF`.

## Cells

Baselines, programs that run a model:

- **05. llama.cpp on a published GGUF file.** Builds llama.cpp, loads
  `Qwen3-0.6B-Q8_0.gguf`, and records how it tokenises the prompt and the
  next token with its five most probable alternatives. `gguf-dump` records
  what the file says about itself.
- **06. llama.cpp on files it converted itself.** `convert_hf_to_gguf.py`
  turns the safetensors of GPT-2 and of SmolLM2-135M-Instruct into float32
  GGUF; llama.cpp then loads and runs each. Also records the list of
  architectures the converter knows.
- **08. Optimum's exporter.** `optimum-cli export onnx` builds an ONNX graph
  from the library's own definition of the model and compares its outputs
  with PyTorch's as part of the export. The `onnx` checker is then run on the
  result.

What a model's files say about themselves, without running it:

- **01. The Hub API.** Model information, files with sizes, and revision
  history for six repositories.
- **02. safetensors headers.** The tensor inventory of four models, read by
  range request without downloading weights.
- **07. Inspectors on published ONNX files.** The `onnx` checker, Polygraphy
  and onnxslim on the published SmolLM2 and GPT-2 graphs.

Schemas and code generated from samples:

- **03. quicktype.** From three configurations of each of three
  architectures: a JSON Schema per architecture, and Rust and Python types.
  The samples are then validated against the schema inferred from them.
- **04. schema-automator and LinkML.** From the same kind of samples: a
  LinkML schema, and from it OWL, SHACL, a JSON-LD context, JSON Schema and
  Python classes. The samples are validated against the schema.
- **10. ONNX's own schema.** `onnx.proto` to JSON Schema with a protoc
  plugin, then into LinkML, then OWL and SHACL.

Translations between representations:

- **09. ONNX2RDF.** A published graph to N-Quads, loaded into Oxigraph and
  counted by class.
- **11. IREE's ONNX importer.** Published graphs into MLIR.
- **12. ONNX Runtime's model builder.** Builds an ONNX graph for
  SmolLM2-135M-Instruct; the `onnx` checker is run on the result.

## Expected

- **03 and 04, controls.** GPT-2's configurations are validated against the
  schema inferred from the llama configurations. That step is expected to
  fail. If it passes, the inferred schema constrains nothing.
- **06.** For GPT-2, llama.cpp is expected to tokenise the prompt as batch
  0001 recorded (464, 3139, 286, 4881, 318) and to rank the same next tokens
  that PyTorch and ONNX Runtime did there (` the` 0.0846, ` now` 0.0479,
  ` a` 0.0462, ` France` 0.0324, ` Paris` 0.0322). A difference would be
  an error in one of three independent programs, or in the conversion.
- **07.** The checker rejects the published SmolLM2 graph and accepts the
  GPT-2 one, as in batch 0001.
- **08.** The exported graphs pass the checker.
- **12.** The builder's graph is rejected by the checker for the operator
  `SimplifiedLayerNormalization`. That would show where the operator in the
  published files comes from.
- **09, 10, 11.** No expectation. These are first contacts.

## Not in this batch

- **Introspection that exists only as a programming interface:** the loading
  report of `transformers`, building a model from its configuration alone,
  `torch.export`, TransformerLens. Calling them takes at least a line of
  code, and whether a line of invocation counts as configuration has not
  been decided.
- **A PyTorch baseline with token probabilities.** No command-line route was
  found; batch 0001's record is used.
- **Language frameworks** (K, SpecTec, IRDL).
