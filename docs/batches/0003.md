# Batch 0003: second baselines

- **Registered:** 2026-10-05, before any cell ran.
- **Status:** not yet run. Results are appended below once CI has produced them.
- **Branch:** `batch/0003-second-baselines`, on top of batch 0002.
  **Workflow:** `.github/workflows/batch-0003.yml`.

## Purpose

Batch 0002 left each of SmolLM2-135M-Instruct and Qwen3-0.6B with one
program's answer to the prompt and nothing to compare it with. This batch
adds the second and third answers: PyTorch through `transformers`, ONNX
Runtime through Optimum, and two more applications. It also asks the library
that defines each architecture to state it, so that the facts llama.cpp and
ONNX Runtime's builder wrote can be checked against a third source.

## Rule for invocations

Where a library has no command line, one invocation is written in a
workflow variable and run as `python -c`. Code-golf rules apply: shortest,
least complex, most robust, most correct. The size of each invocation is
printed with its result, and every run goes through GNU `time`. Nothing
else is written; there are no files of code.

## Cells

Next-token answers (token ids of the prompt, then the five most probable
next tokens with their probabilities):

- **01, 02, 03.** PyTorch through `transformers`: SmolLM2-135M-Instruct,
  Qwen3-0.6B, GPT-2. Each cell also records the library's statement of the
  architecture (configuration, the model built from it, its parameter
  tensors, buffers and module classes), its loading report (missing,
  unexpected and mismatched keys), and the names in the safetensors header
  that the library's parameters lack or add.
- **04.** ONNX Runtime through Optimum on the published SmolLM2 graph, the
  file batch 0001 could not check.
- **05.** ONNX Runtime on the SmolLM2 graph Optimum exports.
- **06.** ONNX Runtime on the published GPT-2 decoder.
- **07.** llama.cpp on Qwen3-0.6B converted from safetensors, so that Qwen3
  has a float32 answer next to the published Q8_0 one.
- **11.** Ollama, on the SmolLM2 file from its own registry, with a raw
  prompt and no template.
- **12.** Text Generation Inference on the CPU, SmolLM2-135M-Instruct.

Structure from the library:

- **08.** TransformerLens's bridge: its configuration of SmolLM2 and its
  next-token answer.
- **09.** `torch.export`: the exported program's signature (parameters,
  buffers, inputs), its node count and its module paths.
- **10.** What three ONNX graphs of SmolLM2 store (published, exported by
  Optimum, built by ONNX Runtime's builder) against the safetensors header:
  nodes, initializers, elements and element types.

## Expected

- **Agreement on tokens.** Every program tokenises the prompt as llama.cpp
  did in batch 0002: 504, 3575, 282, 4649, 314 for SmolLM2 and 785, 6722,
  315, 9625, 374 for Qwen3; and as batch 0001 recorded for GPT-2: 464,
  3139, 286, 4881, 318.
- **Agreement on the answer.** For SmolLM2 the float32 programs (PyTorch,
  ONNX Runtime on both graphs, llama.cpp from batch 0002) rank the same
  five tokens in the same order, with probabilities within 0.01: ` Paris`
  0.47, ` the` 0.27, ` located` 0.08, ` called` 0.02, ` Le` 0.02. For GPT-2,
  PyTorch and ONNX Runtime reproduce batch 0001: ` the` 0.0846, ` now`
  0.0479, ` a` 0.0462, ` France` 0.0324, ` Paris` 0.0322. Ollama's Q8_0 file
  and the published Qwen3 Q8_0 file may differ by more.
- **Agreement on the architecture.** The library's configuration of SmolLM2
  gives 30 layers, 9 heads, 3 key/value heads, hidden size 576,
  intermediate size 1536, 8192 positions and 49,152 tokens, as llama.cpp and
  the builder wrote.
- **GPT-2's extra tensors.** The header names only in the header are the
  twelve `h.N.attn.bias`, and the loading report lists nothing missing.
- **08, 09, 11, 12.** First contacts; no expectation beyond running.
