# Batch 0003: second baselines

- **Registered:** 2026-10-05, before any cell ran.
- **Status:** run, with six cells run a second time and cell 10 a third. See Results.
- **Branch:** `batch/0003-second-baselines`, on top of batch 0002.
  **Workflow:** `.github/workflows/batch-0003.yml`.

## Purpose

Batch 0002 left each of SmolLM2-135M-Instruct and Qwen3-0.6B with one
program's answer to the prompt and nothing to compare it with. This batch
adds the second and third answers: PyTorch through `transformers`, ONNX
Runtime through Optimum, and two more applications. It also asks the library
that defines each architecture to state it, so that the facts llama.cpp and
ONNX Runtime's builder wrote can be checked against a third source.

## Rule for invocations

Where a library has no command line, one invocation is written in a
workflow variable and run as `python -c`. Code-golf rules apply: shortest,
least complex, most robust, most correct. The size of each invocation is
printed with its result, and every run goes through GNU `time`. Nothing
else is written; there are no files of code.

**The architecture, stated by the library**

- `transformers` 5.18 builds SmolLM2-135M-Instruct from its configuration
  as 30 layers, 9 heads, 3 key/value heads, head dimension 64, hidden size
  576, intermediate size 1536, 49,152 tokens, 8,192 positions, tied
  embeddings, SiLU, RMS norm: 134,515,008 parameters in 272 tensors, with
  two buffers (the rotary frequencies). The module classes are
  `LlamaAttention`, `LlamaMLP`, `LlamaRMSNorm`, `LlamaRotaryEmbedding`,
  `LlamaDecoderLayer`, `Embedding`, `Linear`. Its loading report has
  nothing missing, unexpected or mismatched, and the safetensors header's
  names equal the library's parameter names exactly.
- That makes four independent statements of SmolLM2's architecture that
  agree: `transformers`, llama.cpp's converter, ONNX Runtime's builder and
  TransformerLens's bridge.
- Qwen3-0.6B: 28 layers, 16 heads, 8 key/value heads, head dimension 128,
  hidden 1024, intermediate 3072, 151,936 tokens; 596,049,920 parameters in
  310 tensors. The header has one tensor the library does not,
  `lm_head.weight`, a stored copy of the tied embedding. llama.cpp's
  converter states the same dimensions.
- GPT-2: 12 layers, 12 heads, width 768, 1,024 positions, GELU (new), tied
  embeddings; 124,439,808 parameters in 148 tensors, no buffers. The header
  holds 160 tensors and 137,022,720 elements; the difference is exactly the
  twelve `h.N.attn.bias` masks. A raw comparison of names fails here
  because the checkpoint omits the `transformer.` prefix; the library's
  loading report, which knows the prefix, is clean.
- `torch.export` gives the library's own computation graph for SmolLM2:
  273 parameter inputs (the tied matrix appears twice), 2 buffers, 2 user
  inputs, 1 output, 2,203 nodes, 397 module paths. 12.7 s, 0.62 GiB.

**Three ONNX graphs of SmolLM2, against the header** (cell 10, third run,
[37409032729](https://github.com/metavacua/lm-normal-form/actions/runs/37409032729))

- The safetensors header: 272 tensors, 134,515,008 elements.
- Optimum's export: 7,426 nodes, 272 float initializers, 134,515,008
  elements. The header's inventory exactly. Its file is 112 MB larger than
  the published one all the same; whatever holds that is not an
  initializer and was not counted.
- ONNX Runtime's builder: 342 nodes, 214 initializers, 135,039,296
  elements. The 524,288 elements beyond the header are the size of the
  rotary cosine and sine tables for 8,192 positions, which `transformers`
  computes at run time from its two buffers.
- The published graph: 460 nodes, 276 initializers, 135,039,298 elements,
  float and int64. That is the builder's count plus two scalars, with 62
  more initializers: consistent with an older version of the same builder.
- Three graphs of one function, with 342, 460 and 7,426 nodes. Which, if
  any, is a normal form is the question R3 holds open.
